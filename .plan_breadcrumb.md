## Approach

`RunnerConfig` already has `workflow_templates: Vec<WorkflowTemplate>` and `resolve_workflow()` checks custom templates before built-ins, so the new-path orchestrator is functionally complete. The gap is that the legacy `RepoPolicy` struct has no `workflow_templates` field, so `select_workflow(issue, policy)` in `workflow.rs` can only ever find built-in templates even when a custom name is mapped via `policy.workflows`. The fix adds `workflow_templates: Vec<WorkflowTemplate>` to `RepoPolicy`, then updates `select_workflow` to resolve the mapped name against custom templates first and fall back to built-ins — mirroring the logic already in `resolve_workflow`. Finally, tests are needed in both `config.rs` (parsing `[[workflow_templates]]` TOML and the custom-overrides-builtin invariant) and `workflow.rs` (custom template selection via `select_workflow`).
